# Section B Phase 2 · Chapter 2.20: Block and Inline

This chapter covers the difference between block-level and inline elements in HTML: flow content versus phrasing content, how they affect nesting and layout, and when to choose one over the other. It builds on Chapter 2.19 (Character Entities and Encoding) and the structure and semantics from earlier chapters; here we focus on content categories, nesting rules, and how they connect to default display. Chapter 2.21 (Script, Style, and Iframe) then covers script, style, and iframe elements and how they fit into the document structure and content model.

## Learning Objectives

By the end of this chapter, you should be able to:
- Distinguish flow content (block-level in normal flow) from phrasing content (inline) and how the HTML content model defines what can nest inside what.
- Know which common elements are block (e.g. div, p, h1–h6, ul, li, section, article) and which are inline (e.g. span, a, strong, em, img) by default.
- Understand nesting rules: flow can contain flow or phrasing; phrasing cannot contain block; some elements have stricter rules (e.g. p cannot contain block).
- Relate HTML content categories to default CSS display and to the box model so you choose the right container for structure and layout. Phase 7 (CSS) will build on this when you control display and the box model explicitly.

## Key Terms

- **flow content**: Content that typically participates in the document flow; most flow elements are block-level by default (e.g. div, p, section, article, ul, li). Flow content can usually contain other flow content and phrasing content; some flow elements (e.g. p) can contain only phrasing.
- **phrasing content**: Content that is inline: runs in lines of text (e.g. span, a, strong, em, img). Phrasing content cannot contain block-level (flow) elements; it can contain other phrasing content.
- **block-level**: In CSS terms, an element that generates a block box: it typically starts on a new line and stretches to fill the available width (unless CSS changes it). In HTML, most flow content is block-level by default (e.g. div, p, section).
- **inline**: In CSS terms, an element that generates an inline box: it sits in a line of text and does not start a new line by itself. In HTML, phrasing content is inline by default. You can change display with CSS (e.g. display: block on a span), but the HTML content model does not change: the element still cannot validly contain block-level children.

## 1) Flow Content and Phrasing Content

HTML groups elements into content categories. Flow content is the broad category that includes most elements that represent blocks of content: div, p, headings (h1–h6), section, article, main, header, footer, nav, aside, ul, ol, li, and so on. These elements are typically block-level: they start on a new line and stack vertically in the normal document flow. Phrasing content is the category for inline content: text and elements that sit inside lines of text, such as span, a, strong, em, img, and similar. Phrasing content does not start a new block; it flows with the text.

The content model determines what can nest inside what. Flow content can usually contain other flow content and phrasing content. So a div can contain paragraphs, lists, sections, and also spans and links. A section can contain headings, paragraphs, and other flow or phrasing. Phrasing content cannot contain flow content. So a span cannot contain a div or a paragraph; an anchor (a) cannot contain a block-level element in HTML5 (with limited exceptions for transparent content). If you put a div inside a span, the HTML is invalid because span is phrasing and div is flow. The parser may "fix" invalid nesting by closing the span before the div, which can produce an unexpected DOM and layout. So knowing which elements are flow and which are phrasing helps you write valid markup and avoid surprises.

Common flow (block-level) elements include div, p, h1 through h6, ul, ol, li, section, article, main, header, footer, nav, aside, figure, figcaption, blockquote, pre, and form. Common phrasing (inline) elements include span, a, strong, em, img, br, input (when not used as block), label, and small. Some elements are flow but can contain only phrasing (e.g. p can contain only phrasing content, not other paragraphs or divs). That is why you cannot put a div inside a p: p is flow but its content model is phrasing only. Heading elements (h1–h6) are also flow and typically have a phrasing-only content model (they can contain phrasing like span and a but not block elements like div or p). So the rule is not just "flow contains flow"; it is "each element has a specific content model." For p and headings, that model is phrasing only. For div, section, article, main, and similar, the model allows flow and phrasing, so they can contain other blocks and inline content. Use the content model when you are unsure: if the child is a block (e.g. another p, a div, a list), the parent must allow flow content and the specific parent must allow that child. The HTML spec defines content models for each element; in practice, remembering "flow can contain flow and phrasing; phrasing cannot contain flow; p can contain only phrasing" covers most cases. Elements like header, footer, main, section, and article are flow and can contain flow and phrasing, so they can wrap sections, paragraphs, lists, and inline content. Elements like strong and em are phrasing and can contain only phrasing, so they can wrap text and other inline elements but not divs or paragraphs.

## 2) Nesting Rules

Valid nesting follows the content model. A div can contain flow and phrasing, so you can put paragraphs, lists, sections, and spans inside a div. A p can contain only phrasing content, so you cannot put a div, another p, or a list inside a p. If you do, the browser will close the p when it sees the block element, so you may get two separate paragraphs or a broken structure. For example, if you write a p that contains a div, the parser will close the p before the div; the div will be a sibling of the p, not a child. That can break your intended structure and styling (e.g. CSS that targets "div inside p" will not match).

An anchor (a) in HTML5 cannot contain interactive content (e.g. a button or another link) and, in practice, is phrasing content: it flows with text. Do not put block-level elements inside an a in a way that would make the anchor wrap a div or p; the spec restricts what can be inside a. Use the anchor for inline content (text, span, img) and wrap block-level content in a div or other flow element, then make that block a link with JavaScript or use the block's content as separate links. Buttons are flow when used as block-level controls but can be inline in some contexts; a button cannot contain interactive descendants. Lists: ul and ol contain only li (and script or template in some cases); li can contain flow content. So the nesting chain is: flow container (e.g. body, main, section) can contain flow (div, p, section, ul) and phrasing (span, a); p can contain only phrasing; phrasing (span, a) cannot contain flow (no div or p inside span).

When you choose a container, ask: is this content a block (paragraph, list, section) or inline (a few words, a link, an emphasis)? Use a block-level element (p, div, section, etc.) for blocks; use an inline element (span, a, strong, em) for inline. Do not put block inside inline. If you need a block that contains both blocks and inline runs, use a flow container (div, section, article); if you need only inline, use phrasing (span or the appropriate inline element). That keeps nesting valid and the DOM predictable. Some elements have mixed or transparent content models (e.g. certain elements can contain "flow" or "phrasing" depending on context); when in doubt, stick to the simple rule: block containers get flow children (div, section, p, list), and inline containers get phrasing children (span, a, strong, em). Validators will report errors when nesting is wrong, and fixing those errors usually means moving a block out of phrasing or out of p, or changing the parent to a div or section.

## 3) Default Display and the Box Model

In CSS, every element generates a box. Block-level elements (those with display: block by default) generate block boxes: they start on a new line and typically take the full width of their container. Inline elements (display: inline by default) generate inline boxes: they sit in a line and do not start a new line; their width is determined by their content (and padding/border). The box model (content, padding, border, margin) applies to both; but block boxes stack vertically and inline boxes flow in lines. Phase 7 (CSS) will go deeper into the box model and display; here the point is that the HTML content category (flow vs phrasing) usually matches the default display (block vs inline), so choosing the right element gives you the right default layout.

Some elements have display: inline-block or other values by default (e.g. img is inline but replaced). You can change display with CSS (e.g. make a span display: block), but the HTML content model does not change: a span is still phrasing content and cannot validly contain a div, even if you make the span block-level with CSS. So validity is about the HTML nesting; layout is about CSS. When you want a block that has no semantic meaning, you use div (flow content, block by default). When you want inline content that has no semantic meaning, you use span (phrasing content, inline by default). When you want a paragraph, you use p (flow content, block by default, but p can contain only phrasing). Choosing the right element keeps both the HTML valid and the default layout correct; you can then adjust layout with CSS without changing the element type. In Phase 7 (CSS) you will use display (block, inline, flex, grid, etc.) to change how elements are laid out; the HTML element still determines the content model and default behavior. So use HTML for structure and semantics (flow vs phrasing, and the right semantic element when it exists), and use CSS for visual layout. That separation makes it easier to maintain and to adapt the design without breaking the document structure.

## 4) Choosing the Right Container

Use a block-level (flow) element when the content is a block: a paragraph, a list, a section, a group of blocks. Use div when the block has no semantic meaning (e.g. a layout wrapper or a grid row). Use p when the content is a paragraph (one or more sentences of text). Use section, article, main, header, footer, nav, or aside when the block has that semantic role. Use ul or ol when the content is a list. Do not use p when you need to wrap blocks (e.g. a heading and a list); use div or section, because p cannot contain block-level children. Use an inline (phrasing) element when the content is inline: a few words, a link, an emphasis, or an image in a line of text. Use span when the inline content has no semantic meaning (e.g. a styling or scripting hook). Use a, strong, em, or other inline elements when they match the meaning.

Structure and semantics drive the choice. If you have a dashboard with several sections (e.g. "Battery status", "Solar production"), each section is a block; use section (or div if it has no heading/theme) and put the content inside. If you have a sentence that includes a number you want to style or update (e.g. "Voltage: 12.4 V"), the number can be in a span; the sentence is in a p, and the span is phrasing inside the p. If you have a list of links (e.g. navigation), use ul and li with a inside each li; the a is phrasing inside the li (flow). If you have a card that contains a heading, a paragraph, and a button, the card is a block (div or article); the heading, paragraph, and button are flow; the card cannot be a p because p cannot contain those blocks. Homestead pages mix flow (sections, cards, lists, forms) and phrasing (labels, links, values in a line of text); choosing the right container keeps the document valid and the layout predictable. When you add a new block (e.g. a "Fence status" section or a "Drip zones" list), use a flow element (section, div, ul) as the container and put flow or phrasing inside as appropriate. When you add a run of text that needs styling or scripting (e.g. a sensor name or a threshold value in a sentence), use a phrasing element (span or the right semantic inline element) inside the paragraph or heading. Keeping this habit—block containers for blocks, inline elements for inline runs—makes it easier to add new content without introducing invalid nesting and helps the document stay valid as it grows.

## 5) When to Use What

Use flow (block-level) elements for blocks: div for neutral blocks, p for paragraphs, section for thematic groups with a heading, article for self-contained units, ul/ol/li for lists, and so on. Use phrasing (inline) elements for inline content: span for neutral inline, a for links, strong for strong emphasis, em for emphasis, img for images in text. Do not put flow inside phrasing: no div or p inside span or a. Do not put block inside p: no div, no other p, no list inside a paragraph. Use div or section when you need to group blocks (e.g. a heading plus a list plus a paragraph). Use p when you have a single paragraph of text (which can contain spans, links, and other phrasing). Use span when you need to wrap a word or phrase for styling or scripting without adding block structure. When in doubt, if it is a chunk that starts on its own line and contains other chunks or full sentences, use a block element (div, p, section, etc.); if it is a run of text within a line, use an inline element (span, a, strong, em). If you need to group several blocks (e.g. a heading, a paragraph, and a list), the parent must be a flow container that allows flow children (div, section, article); it cannot be a p. If you need to wrap a single word or number for styling or scripting, use span (phrasing) inside the paragraph or heading. Lists (ul, ol) are flow; each item (li) is flow and can contain flow content (e.g. paragraphs, divs, or more lists). Forms are flow; the form contains form controls and labels, which may be inline or block in layout but follow the same nesting rules: do not put block inside phrasing, and do not put block inside p.

## 6) Homestead Examples: Block and Inline in Practice

On a homestead dashboard, the main content is flow: a main element contains sections (e.g. "Battery status", "Solar production", "Coop status"). Each section is a block; inside it you might have a heading (block), a paragraph or two (block), and a list or table (block). So the structure is flow inside flow. Within a paragraph (e.g. "Battery voltage is 12.4 V."), the number "12.4" might be in a span so you can style it or update it via script; the span is phrasing inside the p. A button or link is flow or phrasing depending on context; the label on a button can be text (phrasing) inside the button. A nav contains a list (ul with li); each li contains an a (link); the a is phrasing inside the li. That is valid: flow (nav) contains flow (ul, li), and li contains flow (the a in many specs is flow when it wraps block, but a simple text link is phrasing inside li).

For a sensor card (e.g. freezer temperature), the card might be an article (flow). Inside it: a heading (flow), a paragraph with the current value (flow; the value may be in a span for scripting), and maybe a button (flow). All flow inside flow. For a coop door control, a div or section wraps the control; inside you might have a label (inline or flow depending on use), an input or button (flow in layout), and perhaps a span that shows status (phrasing if it is one short line). For drip irrigation zones, a section might contain a heading and a list of zones; each zone might be an li containing a div (flow) with the zone name and controls. For alert messages, each alert might be a block (div or article); the text inside can be paragraphs and spans. For forms, the form is flow; inside it you have labels, inputs, and buttons. Labels and inputs are often inline or inline-block in layout, but the form and its structure are flow. Keeping blocks for structure (sections, cards, lists) and inline for runs of text (spans, links, emphasis) keeps the markup valid and makes it easier to style and script. For electric fence or energizer status, a section (flow) can contain a heading and a div or p with the voltage and status text; the voltage value can be in a span (phrasing) inside the paragraph. For soil moisture or garden sensors, each sensor block is flow (div or article); the reading text can be a paragraph with a span for the numeric value. For a Raspberry Pi or ESP32 device list, use ul and li (flow); each li can contain a div (flow) with the device name and status, and the name or status can include spans (phrasing) for styling. For forms, the form element is flow; inside it you have label, input, and button. Labels and inputs are often inline or inline-block in layout, but they are still flow or phrasing as defined by HTML; the form itself is the block container. For alert history or log tables, the table is flow; cell content can be paragraphs or spans as needed. In every case, use block elements to create the structure (sections, cards, rows, lists) and inline elements only where content is truly inline (a phrase, a number, a link).

## 7) What Breaks When Nesting or Content Model Is Wrong

Putting a block element inside phrasing (e.g. a div inside a span) is invalid. The browser may close the span when it sees the div, so the div becomes a sibling of the span and the structure is wrong. Fix by not putting block inside inline; use a block container (div, section) for the block content. Putting a block inside a p (e.g. a div or another p inside a paragraph) is invalid; the parser will close the p, so you get unexpected structure. Fix by using a div or section to wrap the blocks instead of a p. Putting interactive content inside an anchor (e.g. a button inside an a) is invalid or problematic. Fix by not nesting interactive elements; use a button or a link, not both wrapped.

Using the wrong element for the content type can also break layout or semantics. If you use a span where you need a block (e.g. wrapping several paragraphs in a span to style them), the span cannot validly contain those paragraphs; use a div. If you use a p where you need to contain blocks (e.g. a heading and a list inside a p), the p will be closed before the heading or list; use a div or section. If you use a div for a single paragraph of text, it is valid but p is more semantic; prefer p for paragraphs. Putting a heading (h1–h6) inside a p is also invalid because headings are flow and p can contain only phrasing; the parser will close the p before the heading. Fix by making the heading and paragraph siblings inside a div or section. These rules exist so the document structure is well-formed and so assistive technology and other tools can interpret the hierarchy correctly. Testing with a validator (e.g. W3C) helps catch invalid nesting. Inspecting the resulting DOM in dev tools shows how the parser actually structured the document; if you see unexpected siblings or closed tags, check the nesting rules. A common mistake is wrapping a div (e.g. a "card" or "row") inside a p to get a paragraph-style margin; the parser will close the p before the div, and the div will sit outside the paragraph. Fix by using a div or section as the outer container and putting the paragraph inside it if you have paragraph text, or by not using a p when the content is not a single paragraph. Another mistake is putting a list (ul or ol) inside a p; lists are flow content and cannot be inside p. Fix by making the list a sibling of the paragraph, both inside a div or section.

## 8) Checklist for Block and Inline

When you add or change structure, use this list. Use flow (block-level) elements for blocks: div, p, section, article, ul, ol, li, and so on. Use phrasing (inline) elements for inline content: span, a, strong, em, img. Do not put block inside phrasing: no div or p inside span or a. Do not put block inside p: no div, no other p, no list inside a paragraph. Use div or section (not p) when you need to group multiple blocks (e.g. a heading and a list). Use p for single paragraphs of text; the content of p must be phrasing only. Use span for inline runs (words, numbers) that need styling or scripting; use div for block-level wrappers. When you have a card or section that contains a heading, text, and controls, use a block container (div, section, article); do not try to put that inside a p. Validate the document to catch invalid nesting. When you add a new section or card, ensure its children are valid: use div or section (not p) as the wrapper if the children include headings, lists, or multiple paragraphs. When you add a sentence with a value or term that needs styling, put the value or term in a span inside the paragraph. ## Common Pitfalls

Putting block inside p: A paragraph cannot contain div, another p, or a list. The parser will close the p; use div or section to wrap blocks.

Putting block inside phrasing: Span and a cannot contain div or p. Use a block container for block content; use span or a only for inline content. The parser will fix invalid nesting by closing the inline element early.

Using div for a single paragraph: Prefer p for paragraphs so the content model and semantics are correct. Use div for neutral block containers.

Using span for block-level grouping: If you need to wrap blocks (e.g. several paragraphs), use div or section. Span is for inline only.

Ignoring nesting when copying markup: If you copy a structure from elsewhere, check that the parent allows the children (flow vs phrasing, and specific rules like p). Invalid nesting can cause the parser to close tags early and change the DOM.

Assuming CSS display changes HTML validity: Making a span display: block does not allow the span to contain a div. Validity is determined by the HTML content model, not CSS. Always check nesting in the HTML; do not rely on CSS to "fix" invalid structure.

## Summary

Flow content (block-level by default) includes div, p, headings, section, article, lists, and similar; it can contain other flow and phrasing. Phrasing content (inline by default) includes span, a, strong, em, img; it cannot contain block-level elements. Nesting rules: do not put block inside phrasing; do not put block inside p (p can contain only phrasing). Choose the right container: block elements for blocks (paragraphs, sections, lists), inline elements for inline runs (words, links, emphasis). Homestead dashboards use flow for structure (main, sections, cards, lists, forms) and phrasing for text runs (spans for values, links in nav, emphasis). Valid nesting keeps the DOM predictable and avoids parser corrections. Use the checklist in section 8 when you add or change structure so flow and phrasing are used correctly and nesting stays valid.
