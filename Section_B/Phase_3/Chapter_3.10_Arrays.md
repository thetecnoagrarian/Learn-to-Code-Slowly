# Section B Phase 3 · Chapter 3.10: Arrays

This chapter covers array literals, indexing, length, mutation (push, pop, shift, unshift, splice), and the common transformation methods map, filter, and reduce. It builds on Chapter 3.09 (Objects): arrays are objects with numeric string keys and a length property, and you use objects (e.g. sensor objects) as array elements. Chapter 3.11 (Strings and Template Literals) then covers string methods and template literals; strings are iterable like arrays but immutable. Arrays are the main way you represent ordered lists (sensors, zones, readings) and work with them using iteration (Chapter 3.06) and callbacks (Chapter 3.07). Many APIs return arrays of objects; you will map, filter, and reduce them to build UI or compute summaries.

## Learning Objectives

By the end of this chapter, you should be able to:
- Create arrays with literals and access elements by index (0-based); use length and understand sparse arrays.
- Mutate arrays with push, pop, shift, unshift, and splice; know which methods mutate in place and which return a new array.
- Use map, filter, and reduce for transformation and aggregation; chain them for data pipelines.
- Iterate with for...of and with forEach, map, filter, and reduce; choose the right tool for the job.

## Key Terms

- **array literal**: A value written as [ item1, item2, ... ]. Creates a new array; elements can be any type. Empty array is [].
- **index**: The position of an element, starting at 0. You access with array[index]. Indices are converted to strings (array["0"] is the first element).
- **length**: A property of every array; it is one more than the highest index (or the number of elements for a dense array). Writing array.length = n truncates or extends the array.
- **mutating method**: A method that changes the array in place (e.g. push, pop, splice). The same array reference is updated.
- **map**: An array method that returns a new array; each element is the return value of the callback called with that element. Used for transformation.
- **filter**: An array method that returns a new array containing only elements for which the callback returns a truthy value. Used for selection.
- **reduce**: An array method that reduces the array to a single value by calling the callback for each element, passing an accumulator and the element; the callback returns the next accumulator. Used for aggregation.

Arrays preserve insertion order: the first element you push is at index 0, the next at 1, and so on. That order is maintained by for...of, map, filter, reduce, and when you iterate with a for loop. So arrays are ordered collections; plain objects (Chapter 3.09) also have key order in modern JavaScript but are used for key-value data rather than ordered sequences. In earlier phases you saw lists or sequences; in JavaScript the array is the primary ordered collection, and you will use it together with objects (arrays of objects) and with string methods like split and join (Chapter 3.11).

## 1) Creating and Indexing

You create an array with a literal: square brackets and a comma-separated list of elements. The elements can be any type: numbers, strings, objects, other arrays, null, undefined. An empty array is []. You access an element by index: array[0] is the first element, array[1] the second, and so on. Indices are 0-based. The last element is at index length minus one, so array[array.length - 1]. If you use an index that is out of range (negative or >= length), you get undefined. Arrays are objects; the indices are property keys (strings "0", "1", etc.). So typeof [] is "object"; to tell an array from a plain object, use Array.isArray(arr). The length property is automatically maintained: it is one more than the highest index that has been set, or the number of elements in a dense array. If you set array.length = 0, you clear the array; if you set length to a smaller number, elements at that index and beyond are dropped. If you set a property with an index >= length, length increases. The maximum length is limited by the engine (typically around 2^32 - 1); in practice you will not hit that. To create an array filled with a value, you can use Array(n).fill(value); fill mutates and returns the array. Array.from({ length: n }, (_, i) => i) creates [0, 1, ..., n-1]; the second argument is a mapping function. These helpers are useful when you need a range or a fixed-size buffer.

A sparse array has "holes": indices that were never set or were deleted. For example, [1, , 3] has a hole at index 1. length still reflects the highest index plus one. Iteration and many methods skip holes (the callback is not invoked for them), but the behavior can be surprising; prefer dense arrays when you can. For a homestead example: an array of sensor ids ["sensor1", "sensor2"]; an array of reading objects [{ id: "s1", value: 12.3 }, { id: "s2", value: 11.8 }]; access the first with readings[0], the last with readings[readings.length - 1]. You can create an array of a given size with Array(n) or Array.from({ length: n }); the former creates a sparse array of length n; the latter can take a mapping function to fill values. When you get data from an API or from Object.keys(), you often get an array and then index or iterate; checking Array.isArray(data) before calling .map or .length avoids errors when the response is null or a single object. You can assign to an index to update: arr[0] = newValue. That mutates the array. To create an array with one element changed without mutating, use map: arr.map((item, i) => i === index ? newValue : item). Or use slice to copy the parts before and after and concat: [...arr.slice(0, index), newValue, ...arr.slice(index + 1)]. For small arrays or rare updates, mutation is fine; for shared data or when you need history, prefer non-mutating updates.

## 2) Mutating: push, pop, shift, unshift, splice

Arrays can be mutated in place. push(item) adds one or more items to the end and returns the new length. pop() removes the last element and returns it; the array is shortened. unshift(item) adds one or more items to the beginning; existing indices shift. shift() removes the first element and returns it. So push and pop work on the end; shift and unshift work on the beginning. splice(start, deleteCount, ...items) is the general mutator: starting at index start, it removes deleteCount elements and optionally inserts items in their place. So splice(0, 1) removes the first element; splice(1, 0, newItem) inserts newItem at index 1 without removing anything. splice returns an array of the removed elements. To replace one element at index i: splice(i, 1, newItem). To remove the last n elements: splice(arr.length - n, n). Negative start is interpreted as offset from the end in some contexts, but for splice the start index is always from the beginning; use arr.length + negativeIndex if you need to splice from the end. When removing multiple elements in a loop (e.g. remove all that match a condition), iterate backwards (from length - 1 to 0) so that indices do not shift under you, or use filter to build a new array instead. All of these change the array in place; if another variable or property holds the same array reference, they see the change. When you want to keep the original array unchanged, use non-mutating operations: slice() to copy, concat() or spread [...arr] to build a new array, or methods like map and filter that return new arrays. For a homestead example: push new readings onto a list as they arrive; pop to process the oldest; or use shift to take the next zone from a queue. Prefer non-mutating patterns when the array is shared or when you need to compare before and after. slice(start, end) returns a shallow copy of the portion from start up to (but not including) end; slice() with no arguments copies the whole array. concat(other) returns a new array that is the original plus the elements of other; you can concat multiple arrays or values. So [...arr].push(x) does not change arr (you spread into a new array and push to that); arr.concat([x]) or [...arr, x] gives a new array with the extra element. Knowing which methods mutate (push, pop, shift, unshift, splice, sort, reverse) and which return new arrays (slice, concat, map, filter) helps you avoid accidental mutation. unshift and shift are slower than push and pop for large arrays because they shift all indices; for a queue, consider using an index to track the "front" and avoid shifting, or use a dedicated structure if performance matters. For typical homestead dashboards with dozens or hundreds of items, the difference is usually negligible.

## 3) map, filter, reduce

map(callback) calls the callback once per element and returns a new array of the callback's return values. The callback receives (element, index, array). Use map when you want to transform each element into something else (e.g. each sensor object into a display string, or each reading into a status). filter(callback) returns a new array containing only elements for which the callback returns a truthy value. The callback has the same signature. Use filter when you want to keep only some elements (e.g. readings below threshold, or sensors that are enabled). reduce(callback, initialValue) reduces the array to a single value. The callback receives (accumulator, element, index, array) and returns the next accumulator; the first call uses initialValue as the accumulator (or the first element if no initialValue is given, and iteration starts at index 1). Use reduce when you want a single result from the whole array (e.g. sum, max, or building an object). For sum: reduce((acc, n) => acc + n, 0). For max: reduce((acc, n) => n > acc ? n : acc, -Infinity) or use Math.max(...arr) when the array is not huge. For building an object keyed by id: reduce((acc, item) => ({ ...acc, [item.id]: item }), {}). Always pass an initial value when the array might be empty so reduce does not throw. You can chain: arr.filter(...).map(...).reduce(...) so you filter, then transform, then aggregate. The callbacks are the same style as in Chapter 3.07 (functions as values); arrow functions are common for short callbacks. Each method returns a value (map and filter return new arrays, reduce returns the final accumulator), so you can assign the result or pass it to the next method. flatMap(callback) is like map but each callback return value is flattened one level; useful when the callback returns an array and you want a single flat array. For "transform and flatten," flatMap is cleaner than map followed by flat(). For a homestead example: map readings to status strings; filter to readings below threshold; reduce to compute average or find max. These methods do not mutate the original array; they return new values (a new array for map and filter, a single value for reduce).

## 4) Iteration and When to Use What

You can iterate over an array with for...of (Chapter 3.06) to get each value, or with a for loop using an index. The array methods also iterate: forEach(callback) runs the callback for each element (for side effects; it returns undefined). map, filter, and reduce iterate and return a value (new array or single value). Use for...of when you want to loop and do something for each element without building a new array. Use forEach when you want side effects (e.g. update the DOM for each item) and do not need a return value. Use map when you want a new array of transformed values. Use filter when you want a new array of elements that pass a test. Use reduce when you want a single value from the whole array. Do not use for...in for arrays; use for...of or these methods. You can break or return from a for loop or for...of; you cannot break out of forEach, map, or filter—they run to completion. So for "find first match and stop," use a for loop with break or the find() method. forEach does not return a value (it returns undefined); use it when you want side effects only. If you need the index in a for...of loop, you can use entries: for (const [index, value] of arr.entries()) or keep a counter. Many problems are naturally expressed as "filter then map" or "map then filter"; chaining keeps the code linear and readable. For a homestead example: for...of over sensors to render a row each; map to turn sensors into summary objects; filter to only enabled zones; reduce to sum readings or build a lookup by id. sort() and reverse() mutate the array; if you need a sorted copy, do [...arr].sort() so the original is unchanged. sort() by default converts elements to strings and sorts lexicographically; for numbers pass a compare function: (a, b) => a - b for ascending. So readings.sort((a, b) => a - b) sorts numbers; without the function, [10, 2, 1] becomes [1, 10, 2] (string order). includes(item) returns true if the array contains the item (uses strict equality); indexOf(item) returns the first index or -1. These are handy for "is this id in the list?" or "where is this element?".

## 5) Homestead Examples: Arrays in Practice

An array of sensor ids to fetch readings for each; loop with for...of or map over ids to get an array of readings. An array of zone objects with name and enabled; filter to enabled zones, then map to zone names for the UI. An array of battery readings; reduce to average or use Math.max with spread (Math.max(...readings)) to get the max. An array of drip zone statuses; find the first zone that needs water with find(callback) or a for loop with break. Push new readings onto a list and slice(-10) to keep only the last 10. An array of objects from an API; map to extract a field or transform, filter to remove invalid entries, reduce to build a summary. An array of zone names; use indexOf or findIndex to find the index of the selected zone, or find to get the zone object by id. An array of temperature readings from multiple freezers; reduce to { min, max, avg } or use Math.min(...temps) and Math.max(...temps) with spread. An array of sensor objects; map to an array of ids for an API call, or reduce to an object keyed by id for quick lookup. An array of alarm thresholds per zone; use every(threshold => threshold > 0) to validate that all are positive. An array of status strings; use join(", ") to produce a single string for display (Chapter 3.11 will cover join in detail). When you have a list of items to process in order (e.g. zones to run one after another), the array is the natural structure; loop or use forEach and call the async or sync handler for each. When the order of operations matters (filter then map then take first), chain instead of multiple loops. Spread to copy an array so you can sort or mutate the copy without touching the original: [...arr].sort(). sort() by default sorts as strings; for numbers use (a, b) => a - b. includes(item) and indexOf(item) test membership or find the index. Arrays of objects (sensors, zones, readings) are very common; you combine object property access (Chapter 3.09) with array indexing and methods. Chapter 3.11 (Strings) will cover string methods (split, join) that convert between strings and arrays; strings are iterable and immutable. To get the first N or last N elements without mutating, use slice(0, n) or slice(-n). To remove or insert at an index without mutating, use spread and slice: [...arr.slice(0, i), ...arr.slice(i + 1)] to remove, [...arr.slice(0, i), newItem, ...arr.slice(i)] to insert. These patterns support immutable updates when you need to keep the original array.

## 6) What Breaks When Arrays Are Wrong

If you use an index that is negative or past the end, you get undefined; no error. Check bounds if you need to, or use optional chaining when the array might be empty or short. If you mutate an array while iterating over it (e.g. push or splice inside forEach), behavior can be confusing and elements may be skipped or processed twice. Prefer building a new array (map, filter) or iterating over a copy. If you use map or filter but forget that they return new arrays and do not change the original, and you keep using the old reference, you do not see the transformed data. Assign the result: const filtered = arr.filter(...). If you use reduce without an initial value and the array is empty, you get an error. Always provide an initial value when the array might be empty (e.g. reduce((a, b) => a + b, 0)). If you use splice with wrong arguments, you can delete too much or insert at the wrong place; splice(0, 1) removes one at index 0; splice(1, 0, x) inserts x at index 1. If you treat a non-array (e.g. an object or null) as an array and call .map or .length, you get an error. Use Array.isArray(arr) before assuming something is an array, or guard with optional chaining (arr?.length). If you expect an array but the API sometimes returns a single object, normalize: const list = Array.isArray(data) ? data : (data ? [data] : []). If you use map or filter and the callback has side effects (e.g. logging or mutating something else), remember the callback runs for every element; prefer forEach for side effects or a for loop if you need to break early. If you chain map and filter and the array is empty at any step, the rest of the chain still runs and produces an empty array or the reduce initial value—no error, but worth keeping in mind for debugging. So: avoid mutating while iterating, assign map/filter results, provide reduce initial value for empty arrays, and validate that a value is an array when it comes from outside. If you sort an array of objects, pass a compare function that compares the property you care about (e.g. (a, b) => a.reading - b.reading)); otherwise sort uses string conversion and object order is meaningless. If you use splice to remove an element and then use the same array in a loop, remember that indices shift after splice so you may need to decrement an index or iterate backwards when removing multiple elements. If you pass a callback that uses an outer variable and that variable changes between calls (e.g. a loop variable), the callback sees the current value; use let in the loop or capture in a const inside the loop if you need a per-iteration snapshot (same as in Chapter 3.08). If the array is very large and you only need the first match, find() or a for loop with break is better than filter (which processes all elements). If you chain many operations, each step allocates a new array; for huge arrays that can matter, but for typical dashboard sizes it is fine.

## 7) Checklist

When you work with arrays: (1) Use literals [] and 0-based indexing; use length for the count and array[array.length - 1] for the last element. (2) Prefer for...of and array methods (map, filter, reduce, forEach) over for...in. (3) Use push, pop, shift, unshift, splice when you need to mutate; use slice, spread, concat, map, filter when you need to keep the original. (4) Use map for transformation, filter for selection, reduce for aggregation; chain when you need a pipeline. (5) Provide an initial value to reduce when the array might be empty. (6) Use Array.isArray to check for arrays when the value might be an object or null. (7) Avoid mutating the array inside a loop or callback over that array. (8) Use a compare function with sort when sorting numbers or objects (e.g. (a, b) => a - b or (a, b) => a.reading - b.reading). (9) When data from an API might be a single object or null, normalize to an array (Array.isArray(data) ? data : (data ? [data] : [])) before using array methods. Chapter 3.11 (Strings and Template Literals) covers strings, which are iterable and have methods like split and join that work with arrays.

## Common Pitfalls

Using for...in on arrays: You get string indices and possibly other enumerable properties. Use for...of or array methods.

Mutating while iterating: Adding or removing elements during forEach or for...of can cause skipped or repeated elements. Build a new array or iterate over a copy.

Forgetting map/filter return new arrays: They do not change the original. Assign the result to use the transformed or filtered array.

reduce with empty array and no initial value: Throws. Always pass an initial value when the array might be empty.

Treating non-array as array: Calling .map or .length on null or an object fails. Check Array.isArray or use optional chaining.

Off-by-one with length: length is the count; last index is length - 1. slice(0, n) gives n elements; splice(i, n) removes n elements starting at i.

Sorting numbers without compare: sort() converts to strings; 10 comes before 2. Use (a, b) => a - b for numeric sort.

Assuming API returns array: A single object or null will break .map or .length. Normalize with Array.isArray(data) ? data : (data ? [data] : []).

## Summary

Arrays are ordered lists created with literals, indexed from 0, with a length property. Use push, pop, shift, unshift, and splice to mutate; use slice, spread, map, filter, and reduce when you need non-mutating behavior. map transforms, filter selects, reduce aggregates; chain them for pipelines. Use find, some, every for "first match" or "any/all" checks. Iterate with for...of or array methods; avoid for...in. Sort with a compare function for numbers or objects; copy before sorting if you must keep the original order. Use Array.isArray when the value might not be an array. Know which methods mutate (push, pop, shift, unshift, splice, sort, reverse) and which return new arrays (slice, concat, map, filter, spread).
