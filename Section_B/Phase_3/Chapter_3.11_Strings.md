# Section B Phase 3 · Chapter 3.11: Strings and Template Literals

This chapter covers string methods (length, slice, indexOf, includes, trim, split, replace, and case conversion) and template literals for interpolation and multiline strings. It builds on Chapter 3.10 (Arrays): strings are iterable and have methods like split (string to array) and you use join (array to string); you will format display text from numbers, objects, and array data. Chapter 3.12 (Error Handling) then covers how to throw and catch errors, including error messages that are strings. Strings are immutable: every method returns a new string, so you assign the result or use it in an expression. You will use strings for labels, messages, formatted numbers, and for building output from the objects and arrays you learned in the previous chapters.

## Learning Objectives

By the end of this chapter, you should be able to:
- Use common string methods: length, slice, indexOf, includes, trim, split, replace, toLowerCase, toUpperCase.
- Use template literals (backticks) for interpolation with ${expression} and for multiline strings.
- Choose between concatenation with + and template literals for readability; know that strings are immutable.
- Convert between strings and arrays with split and join; format numbers and values for display.

## Key Terms

- **string**: An immutable sequence of UTF-16 code units (characters). You create strings with literals (single, double, or backtick quotes) or with String(value). Once created, a string cannot be changed; methods return new strings.
- **template literal**: A string literal delimited by backticks. It can span lines and can contain ${expression} placeholders; each expression is evaluated and coerced to string and inserted in place. Used for interpolation and multiline strings.
- **interpolation**: Embedding the value of an expression inside a string. In template literals you write ${expression}; the expression is evaluated and its result is converted to string and inserted.
- **immutable**: A value that cannot be changed after creation. String methods do not modify the original string; they return a new string. So you must assign the result or use it (e.g. const trimmed = s.trim();).

Strings can be written with single quotes, double quotes, or backticks. Single and double quotes behave the same; backticks enable template literals. The length property and indexing (str[0]) work like arrays for reading characters, but you cannot assign to an index to change the string. Strings are iterable: for (const char of str) gives each character (or code unit). To combine strings you concatenate with + or use a template literal; both produce a new string.

## 1) String Methods

Strings have a length property (number of code units in the string). slice(start, end) returns the substring from start up to but not including end. If end is omitted, it goes to the end of the string. Negative indices count from the end: slice(-3) is the last three characters. indexOf(substring) returns the index of the first occurrence of the substring, or -1 if not found. lastIndexOf(substring) returns the last occurrence. includes(substring) returns true or false. So you can test for presence with includes or get the position with indexOf. trim() returns a new string with whitespace removed from both ends; trimStart() and trimEnd() trim only one side. That is useful when you read input (e.g. from a form or config) and want to ignore leading or trailing spaces. toLowerCase() and toUpperCase() return a new string in lower or upper case; use them for case-insensitive comparison (e.g. compare s.toLowerCase() === "yes") or for normalizing display. replace(search, replacement) replaces the first occurrence of search (string or regex) with replacement and returns a new string; replaceAll(search, replacement) replaces all occurrences. split(separator) splits the string into an array of substrings; the separator can be a string or regex. So "a,b,c".split(",") gives ["a", "b", "c"]. If you split with an empty string "", you get an array of single characters. join is an array method (Chapter 3.10): array.join(separator) produces a string. So split and join are the bridge between strings and arrays. For a homestead example: trim a zone name from user input; split a comma-separated list of sensor ids into an array; use toLowerCase to compare a status string; use slice to take the first few characters of a long reading for a tooltip. startsWith(prefix) and endsWith(suffix) return true or false; useful for checking file names or protocol prefixes. padStart(length, padStr) and padEnd(length, padStr) pad the string to a given length (e.g. pad numbers with leading zeros). repeat(n) returns the string repeated n times. When you need to find all occurrences of a substring, you can use a loop with indexOf and a starting index, or use match with a global regex; for simple cases indexOf and a loop are enough. substring(start, end) is similar to slice but does not accept negative indices; slice is more flexible and is usually preferred. charAt(i) returns the character at index i (or "" if out of range); str[i] does the same. When you need to test whether a string contains only digits or matches a pattern, you can use a regular expression (covered later) or loop with character codes; for simple checks, includes or indexOf is enough. String comparison is lexicographic (character by character by code unit); for locale-aware sorting or comparison (e.g. for user-visible lists), there are Intl APIs, but for internal ids and keys the default comparison is fine. When you read from a file or network, you often get a string and then split or parse it; trim and split are the first tools you reach for. concat(...values) is a method that concatenates the given values to the string and returns a new string; in practice you use + or template literals more often. When you need to test whether a string is empty or only whitespace, trim first and then check length: if (str.trim().length === 0). When you need the first or last character, use slice(0, 1) or slice(-1); str[0] and str[str.length - 1] work but return undefined for an empty string, whereas slice returns "" for out-of-range, so slice is consistent. JavaScript strings are UTF-16; most characters are one code unit, but some (e.g. many emoji or characters outside the BMP) are two code units (a surrogate pair). So str.length can be greater than the number of visible characters for such strings. For homestead dashboards with ASCII or common European characters you usually do not need to worry; if you later work with arbitrary Unicode (e.g. user names in many languages), be aware that length and indexing are by code unit. Methods like slice and indexOf work on code units; for character-based length or splitting, you might use [...str].length or Array.from(str) to get character (grapheme) awareness in simple cases.

## 2) Template Literals

A template literal is written with backticks. Inside it you can write ${expression} anywhere; the expression is evaluated and the result is converted to string (via toString or similar) and inserted. So you get "Hello, " + name replaced by `Hello, ${name}`. You can put any expression: a variable, a property (obj.key), a function call, or a more complex expression. The expression runs where the template literal is evaluated. Use template literals when you have several values to embed or when the string spans multiple lines; they are easier to read than long concatenation with +. If you need a literal backtick or ${ in the output, escape with a backslash: \` and \${. Template literals can contain newlines; the newline is part of the string. So you can write a multiline string without using \n. Be aware that indentation inside the backticks is part of the string; if you indent for code readability, the output will have those spaces. Use trim() on the result if you want to remove leading or trailing whitespace from the whole block. For a homestead example: format a status line as `Sensor ${id}: ${reading} ${unit}`; build a short report with several lines and embedded values; or build a URL or message that includes a reading or threshold. You can nest template literals or use expressions that themselves return strings (e.g. `${items.map(i => i.name).join(", ")}`). Keep expressions inside ${} short; if the logic is complex, compute the value in a variable first and then interpolate the variable so the template stays readable. Numbers are coerced to string when interpolated; for controlled formatting use toFixed(n) or toPrecision(n) on numbers before interpolating (e.g. `${reading.toFixed(1)}` for one decimal place). Boolean true and false become "true" and "false". null and undefined become "null" and "undefined". So you can interpolate any value and get a string; for objects you get "[object Object]" unless you use a property or JSON.stringify. Template literals are evaluated when the line runs; if the expression has side effects (e.g. a function call that logs), that side effect happens at interpolation time. Nesting template literals (backticks inside ${}) is allowed and useful when you need a string inside an expression that is itself inside a template.

## 3) Multiline Strings and When to Use What

Before template literals, multiline strings were built with \n in the string or by concatenating several strings. With template literals you can type a real newline and it is preserved. That makes blocks of text (e.g. email body, log message, or help text) easier to write and read. The downside is that the indentation of your code becomes part of the string. If you want the output to start at column 0, either put the first line of the template at column 0 (and accept that the code looks uneven) or build the string with an array of lines and join("\n"), or trim the result. For short strings (one line, one or two values), both "Hello, " + name and `Hello, ${name}` are fine; use whichever is clearer. For several values or multiple lines, prefer template literals. When building URLs or JSON, be careful with user input: do not interpolate raw user input into URLs or JSON without escaping or validation, or you risk injection or broken output. For display text (labels, messages), template literals with variables and simple expressions are ideal. For a homestead dashboard: status text like `Battery: ${reading} ${unit}`; error or info messages that span two or three lines with embedded values; or a list of readings built by mapping an array to strings and then joining with newlines. When to use + vs template literal: for one or two values in a short string, both are clear; for many values or a long string, template literals reduce the chance of missing a space or quote. When building strings in a loop, push segments onto an array and then join("") so you do not create many intermediate strings. When the string is constant (no variables), use ordinary quotes; backticks are for when you need interpolation or newlines. When you need to include a backtick in the output, escape it: \`. When you need literal ${ in the output (e.g. for a code sample or config template), escape: \${. Raw template literals (a tag function) are an advanced feature for custom processing; for normal interpolation and multiline, plain backticks are enough. Performance of string concatenation vs template literals is negligible for typical use; choose based on readability. In a multiline template literal, every newline and space between the backticks is part of the string. If you indent the closing backtick for code style, that indentation is in the string too. To remove it, call trim() on the result or use a helper that strips leading whitespace from each line; for short multiline messages it is often acceptable to leave the indentation or to build the string from an array of lines and join with "\n".

## 4) Homestead Examples: Strings in Practice

Trim and validate user input (zone name, sensor id) with trim() and then check length or pattern. Split a config string (e.g. "zone1,zone2,zone3") into an array with split(","), then map or iterate. Format a reading for display: `${reading.toFixed(1)} ${unit}` so numbers show with one decimal. Build a status line: `Sensor ${id}: ${value < threshold ? "Low" : "OK"}` using a ternary inside the template. Join an array of zone names for a log message: zones.map(z => z.name).join(", "). Parse a simple key=value line with split("=") and trim each part. Use toLowerCase() when comparing user input to allowed values ("on", "off", "auto") so case does not matter. Use slice(0, 20) or similar to truncate a long string for a preview. Replace a placeholder in a message: message.replace("{{name}}", zoneName). Build a multiline alert or email body with a template literal and embedded readings or thresholds. Parse a line like "sensor1=12.3" with split("="), then trim and use the two parts; or use a regex for more complex formats. When building a URL query string from an object, you might join key=value pairs with "&" after encoding each value; template literals help build each pair. When you have a list of labels (e.g. zone names) and want to show "Zone 1: name1, Zone 2: name2", use map and join: zones.map((z, i) => `Zone ${i + 1}: ${z.name}`).join(", "). For a single status line that might be long, use slice(0, maxLen) and append "..." if the string was truncated so the UI does not overflow. Strings tie together numbers (formatted for display), objects (property values interpolated), and arrays (join, split) from Chapters 3.03, 3.09, and 3.10. Build a CSV-like line from an array of values with join(","); parse it back with split(","). Normalize units or labels with toLowerCase before comparing or storing. Use replace to swap a placeholder (e.g. "{{threshold}}") with the actual value when building messages from templates. Build a comma-separated or newline-separated list of readings for a log or email: readings.map(r => `${r.id}: ${r.value}`).join("\n"). Validate that a string is not empty after trim: if (!input.trim()) showError(). Format a date or time string (if you have a Date object, use its methods or Intl; then interpolate into a message). Chapter 3.12 (Error Handling) will use strings for error messages and for converting errors to display text.

## 5) What Breaks When Strings Are Wrong

If you call a string method on a value that is not a string (e.g. null or a number), you get an error. Use String(value) or value?.toString() when the value might be null or undefined, or guard with a check. If you forget that strings are immutable and write s.trim() without assigning the result, the original string is unchanged. Always assign or use the return value. If you use indexOf or includes and expect a number but the substring is not found, indexOf returns -1; check for -1 or use includes for a boolean. If you split with a separator that does not appear in the string, you get an array with one element (the whole string). If you split with an empty string, you get an array of single characters. If you interpolate an object or array directly in a template literal, it is converted with toString(), which for objects gives "[object Object]"; use JSON.stringify when you need the structure, or interpolate specific properties. If you build HTML or shell commands from user input without escaping, you risk injection; escape or validate input. If you use slice or substring with start greater than end, slice returns an empty string; substring swaps the two. If you pass a negative length or invalid index, behavior may differ between methods; prefer slice with valid indices. So: guard non-string values, use the return value of methods, check indexOf for -1, and be careful with user input in interpolated strings. When converting numbers to strings for display, use toFixed(n) for a fixed number of decimals so you do not get long floating-point representation; String(12.3) is "12.3" but very small or large numbers may show in exponent form. If you split by a separator that appears at the start or end of the string, you get empty strings in the array (e.g. "a,b,".split(",") gives ["a", "b", ""]). Filter out empty strings if needed: split(",").filter(Boolean). If you use replace with a string, only the first occurrence is replaced; use replaceAll or a global regex to replace all. When the replacement is dynamic (a function of the match), replace can take a function as the second argument; for simple substitution the string form is enough. When you concatenate many strings in a loop, building an array and then joining is often more efficient than repeated + (each + creates a new string); for a few concatenations or for template literals, the difference is negligible. When comparing strings for equality, use === so type coercion does not surprise you; for case-insensitive comparison, compare s1.toLowerCase() === s2.toLowerCase().

## 6) Checklist

When you work with strings: (1) Use length, slice, indexOf, includes, trim, split, replace, toLowerCase, toUpperCase as needed. (2) Remember all string methods return new strings; assign or use the result. (3) Use template literals for interpolation and multiline strings; use ${expression} for values. (4) Use split to go from string to array and join to go from array to string. (5) Trim user or config input before validating or using. (6) Use String(value) or optional chaining when the value might not be a string. (7) Do not interpolate unsanitized user input into URLs, HTML, or shell commands. (8) Use toFixed or similar when formatting numbers for display so decimals and exponent form are controlled. (9) Prefer slice over substring (slice accepts negative indices). Use includes for "contains" and indexOf when you need the position. Chapter 3.12 (Error Handling) uses strings for error messages and for presenting errors to the user.

## Common Pitfalls

Forgetting strings are immutable: Calling s.trim() or s.toLowerCase() without using the return value leaves s unchanged. Assign the result.

Calling string methods on null/undefined: You get an error. Use optional chaining (s?.trim()) or String(s) or check before calling.

indexOf returns -1 when not found: Check for -1; do not assume a truthy index (0 is valid). Or use includes for a boolean.

Interpolating objects: `${obj}` gives "[object Object]". Use specific properties or JSON.stringify(obj) if you need structure.

User input in templates: Interpolating raw user input into URLs or HTML can cause injection. Escape or validate.

Number to string for display: String(n) or `${n}` can give long decimals or exponent form. Use toFixed(n) for readable numbers.

## Summary

Strings are immutable; methods like slice, indexOf, includes, trim, split, replace, and case conversion return new strings. Use template literals (backticks) for interpolation with ${expression} and for multiline strings. Use split and join to convert between strings and arrays. Trim and validate input; guard when values might not be strings. Use toFixed for number formatting in display. Chapter 3.12 (Error Handling) builds on this with error messages and handling.
