# Section B Phase 3 · Chapter 3.17: Array Methods and Iteration

This chapter goes deeper into array methods and iteration patterns: map, filter, reduce, and forEach; find, findIndex, some, every, flat, flatMap, and sort; when to use which; and how to avoid mutating the array while iterating. It builds on Chapter 3.10 (Arrays), which introduced arrays, indexing, and the basics of map, filter, and reduce. The data you work with—sensor lists, zone lists, readings from an API—often comes as arrays (e.g. from JSON.parse in Chapter 3.16); these methods let you transform, filter, and aggregate that data without writing loops by hand. Chapter 3.18 (Template Literals and Interpolation) then covers how to build strings; you will often map or reduce an array to a string or use template literals to format each item when rendering. Choosing the right method by intent (transform, filter, accumulate, or side effect) keeps code readable and avoids common bugs.

## Learning Objectives

By the end of this chapter, you should be able to:
- Use map to transform each element into a new value and get a new array; use filter to keep only elements that pass a test; use reduce to produce a single value (sum, max, grouped object) from the array.
- Use forEach for side effects only (e.g. update DOM, log); understand that forEach does not return a useful value and you cannot break out of it.
- Use find and findIndex to get the first element or index that matches; use some and every to test whether any or all elements satisfy a condition; use flat and flatMap when working with nested arrays.
- Prefer immutable patterns (methods that return new arrays) over mutating while iterating; know when to use a for loop or for...of instead of array methods (e.g. when you need to break early).

## Key Terms

- **map**: An array method that calls a callback for each element and returns a new array of the callback's return values. Used when you want to transform every element (e.g. each reading into a display object). Does not mutate the original array.
- **filter**: An array method that returns a new array containing only elements for which the callback returns a truthy value. Used when you want to keep a subset (e.g. readings above a threshold). Does not mutate the original array.
- **reduce**: An array method that reduces the array to a single value by repeatedly calling the callback with an accumulator and the current element; the callback returns the next accumulator. Used for sum, max, grouping, or building an object. Takes an initial value; use it when the array might be empty.
- **forEach**: An array method that runs a callback for each element. Used for side effects only; it returns undefined. You cannot break or return a value from forEach; use a for loop or find if you need to stop early.
- **find / findIndex**: find returns the first element for which the callback returns true, or undefined. findIndex returns the index of that element, or -1. Use when you need the first match and want to stop searching.
- **some / every**: some returns true if the callback returns true for at least one element; every returns true if the callback returns true for every element. Use for validation or existence checks (e.g. "does any reading exceed the limit?", "are all zones enabled?").

## 1) map, filter, reduce, and forEach

map takes a callback that receives (element, index, array) and returns a new array where each element is the return value of the callback for the corresponding original element. So you get a one-to-one transformation: same length, possibly different type. Use map when the intent is "turn each item into something else": each sensor object into a display string, each reading into a status object, or each id into a URL. The original array is unchanged. filter takes a callback that returns true or false (or truthy/falsy); the result is a new array containing only the elements for which the callback returned true. Use filter when the intent is "keep only some": readings below a threshold, zones that are enabled, or items that have a required field. You can chain filter then map: first narrow the set, then transform. reduce takes a callback (accumulator, element, index, array) and an initial value. The callback returns the next accumulator; reduce returns the final accumulator. Use reduce when you want a single value from the whole array: sum (accumulator starts at 0, add each element), max (accumulator holds the maximum so far), or building an object keyed by id (accumulator is an object, add a property for each element). Always pass an initial value when the array might be empty; otherwise reduce throws on an empty array when it tries to use the first element as the initial accumulator. forEach runs the callback for each element but ignores the return value and returns undefined. Use forEach when you want side effects: update the DOM for each item, log each one, or call an API for each id. Do not use forEach when you need to build a new array (use map or filter) or a single value (use reduce), or when you need to stop early (use a for loop or find). For a homestead example: map an array of readings to an array of "temperature and label" objects for the UI; filter readings to only those from the last hour; reduce to compute the average temperature or to build a lookup object by sensor id; forEach to append a row to the DOM for each zone. Chaining is common: readings.filter(r => r.value != null).map(r => ({ id: r.id, display: formatTemp(r.value) })). That way you express "filter then transform" in one pipeline. The callback you pass to map, filter, or reduce can be a function reference (e.g. parseFloat) when the signature matches: map expects (element, index, array) and if you only need the element, a function of one argument works. For reduce, the callback must take at least two arguments (accumulator and current element); the initial value type should match what you want the accumulator to be (number for sum, object for grouping). If you return the same accumulator object from reduce and mutate it inside the callback (e.g. acc[key] = value; return acc), you are reusing one object; that is valid and avoids creating a new object per element, but then you must not use that object elsewhere as an immutable snapshot. If you return a new object each time (e.g. { ...acc, [item.id]: item }), you get a new object per step—clearer for reasoning but more allocations. For small and medium arrays the difference is usually negligible. forEach is not chainable in a useful way because it returns undefined; you can call it at the end of a chain (e.g. arr.filter(...).forEach(...)) to run a side effect on the filtered list.

## 2) find, findIndex, some, every, flat, flatMap, and sort

find(callback) returns the first element for which the callback returns true, or undefined if none match. findIndex(callback) returns the index of that element, or -1. Use find when you need "the first item that matches" and do not need to scan the rest of the array. For example: the first zone that is offline, or the first reading that exceeds the limit. some(callback) returns true if the callback returns true for at least one element; otherwise false. every(callback) returns true if the callback returns true for every element; otherwise false. Use some for "is there any that...?" and every for "do all...?". For example: some(readings, r => r.value > maxTemp) to check if any reading is over the limit; every(zones, z => z.enabled) to check that all zones are enabled. flat(depth) flattens nested arrays; by default depth is 1, so one level of nesting is removed. flatMap(callback) is equivalent to map(callback).flat(1): each element is transformed by the callback (which can return an array), and the results are concatenated into one flat array. Use flatMap when you want to "map and then flatten one level": for example, each zone has an array of sensor ids and you want one array of all sensor ids from all zones. sort(compareFunction) sorts the array in place and returns the same array (so the original is mutated). Without a compare function, sort converts elements to strings and sorts lexicographically, so [10, 2, 1] becomes [1, 10, 2]. For numbers, pass (a, b) => a - b for ascending or (a, b) => b - a for descending. For objects, pass a function that compares the property you care about: (a, b) => a.reading - b.reading. If you need to sort without mutating, copy first: [...arr].sort(compare). For a homestead example: find the first sensor that needs calibration; findIndex to get the position of the selected zone in a list; some to see if any alarm is active; every to validate that all config entries have a required field; flatMap to collect all sensor ids from an array of zone objects; sort readings by timestamp or by value for display. flat(depth) with depth greater than 1 flattens multiple levels; flat(Infinity) flattens all nesting. flatMap only flattens one level; if your callback returns nested arrays and you want one flat list, use flatMap and return a flat array from the callback, or map and then flat(Infinity). sort is stable in modern JavaScript: elements that compare equal keep their relative order. That matters when you sort by one field (e.g. status) and want a secondary order (e.g. name) for ties; you can sort by name first, then sort by status, and names stay in order within the same status. includes(value) and indexOf(value) are useful for primitives; for objects they use reference equality, so they will not find an object that looks the same but is a different reference. Use find with a predicate when you need to match by property (e.g. find(z => z.id === targetId)). When you need the last matching element instead of the first, you can reverse a copy and find: [...arr].reverse().find(callback), or use findLast and findLastIndex if your environment supports them.

## 3) Iteration Patterns and When to Use a Loop

Prefer methods that return new arrays (map, filter) or a single value (reduce) when the intent is transformation, filtering, or aggregation. That keeps the original data unchanged and makes the pipeline easy to read. Avoid mutating the array while you iterate over it: if you push, pop, splice, or shift inside a forEach or for...of loop, indices shift and you can skip elements or process the same element twice. Instead, build a new array with filter (to remove elements) or build the result with map and then assign it. If you must remove elements in place, iterate backwards (from length - 1 down to 0) so that removing an element does not change the indices of elements you have not yet visited. When you need to stop as soon as you find something, do not use forEach, map, or filter—they always run to completion. Use find (to get the element), findIndex (to get the index), or a for loop or for...of with break. When you need to do something for each element and also need the index, the callback in map, filter, forEach, and reduce receives the index as the second argument; or use for...of with entries: for (const [i, item] of arr.entries()). When the array might be null or undefined, guard before calling a method: arr?.filter(...) or if (Array.isArray(arr)) { arr.map(...) }. When you have a long chain (filter then map then filter then reduce), each step allocates a new array; for typical dashboard sizes (dozens or hundreds of items) that is fine. For very large arrays, a single for loop that does everything in one pass might be faster, but readability usually wins until you measure a problem. When you need to iterate over something that is not an array but is array-like (e.g. the result of document.querySelectorAll), you can use Array.from(arrayLike).map(...) or [...arrayLike].map(...) to get an array and then use methods. For a homestead example: do not splice inside forEach over zones; instead zones.filter(z => z.enabled) to get a new array of enabled zones. Use find to get the first reading that failed validation and stop; use a for loop with break when you need to both find and do something with the index (e.g. remove that item with splice after the loop). When you have async work inside the callback (e.g. you want to await something for each element), forEach does not wait for promises; the callbacks fire and return promises that are not awaited. Use a for...of loop with await inside it so each iteration waits, or use Promise.all with a map that returns promises if you want to run the async work in parallel and then proceed. So: for sequential async per element, for...of with await; for parallel async per element, Promise.all(arr.map(async (item) => { ... })). When the array is from an API and might be null or undefined, use optional chaining: data?.zones?.filter(...) ?? [] so you get an empty array when data or zones is missing instead of throwing.

## 4) When to Use What

Use map when you want a new array of the same length, each element transformed. Use filter when you want a new array containing only elements that pass a test. Use reduce when you want one value from the whole array (number, object, or other). Use forEach when you want side effects only and do not need a return value or early exit. Use find when you need the first matching element; use findIndex when you need its index. Use some when you need "at least one matches"; use every when you need "all match." Use flat when you have nested arrays and want one level (or more) flattened. Use flatMap when you would do map and then flat(1). Use sort when you need to reorder; copy first with [...arr] if you must not mutate. Chain when the steps are independent: filter then map then slice(0, 10) is "filter, then transform, then take first 10." Do not chain for side effects that depend on the previous step in a complex way; a for loop may be clearer. When the data comes from an API (Chapter 3.16), it is often an array of objects; you will filter by status or date, map to display shape, and reduce for totals or lookups. When you have an array of primitives (numbers, strings), map and filter work the same; reduce can sum or concatenate. When you have sparse arrays (holes), most methods skip the holes; the result may have fewer elements than the length. Prefer dense arrays when you can. When you need to combine two arrays by a key (e.g. zones and their latest readings), you can build a lookup with reduce (readings by zone id) and then map over zones to attach the reading: const byZone = readings.reduce((acc, r) => ({ ...acc, [r.zoneId]: r }), {}); zones.map(z => ({ ...z, reading: byZone[z.id] })). That pattern—reduce to lookup, then map to attach—is common when joining data from different sources. When the transformation or filter is expensive, doing it in one reduce instead of filter then map avoids two passes; but two passes are usually clearer. When you want to partition an array into two (e.g. valid and invalid), you can use reduce to build { valid: [], invalid: [] }, or run filter twice (once for valid, once for invalid); the two filters are two passes but very readable. When you need to find all indices that match (not just the first), use reduce to collect indices, or map to [index, element] then filter then map to index. When you need the original index after a filter, map the array to [element, index] first, then filter, then map back; or use reduce to build an array of { item, index } for items that pass. For homestead code: sensor lists and zone lists are arrays; readings are often arrays of objects; use filter for "only active" or "only last 24h," map for "to display format," reduce for "average" or "lookup by id," and find or some/every for validation or "first match."

## 5) Homestead Examples

Filter readings by threshold: readings.filter(r => r.value != null && r.value < maxTemp) to get only readings that are below the limit. Map to display values: readings.map(r => ({ id: r.id, label: r.name, value: formatTemp(r.value) })) so the UI receives a consistent shape. Reduce for totals: readings.reduce((sum, r) => sum + (r.value ?? 0), 0) / readings.length for average, or reduce((acc, r) => ({ ...acc, [r.sensorId]: r }), {}) to build a lookup by sensor id. Find the first zone that is offline: zones.find(z => z.status === "offline"). Check if any reading is stale: readings.some(r => isStale(r.timestamp)). Validate config: config.sensorIds.every(id => typeof id === "string"). FlatMap sensor ids from zones: zones.flatMap(z => z.sensorIds) to get one array of all sensor ids. Sort zones by name: [...zones].sort((a, b) => a.name.localeCompare(b.name)). Sort readings by value descending: [...readings].sort((a, b) => b.value - a.value). ForEach to render: zones.forEach(z => renderZoneRow(z)). Chain: readings.filter(r => r.value != null).map(r => r.value).reduce((a, b) => a + b, 0) / readings.filter(r => r.value != null).length for average of valid readings (or use reduce once to both sum and count). Get the last N readings: readings.slice(-N). Get readings for a specific sensor: readings.filter(r => r.sensorId === id). When you have an array of log entries, filter by date range, map to a summary string, or reduce to a count; when you have an array of zone configs, use every to validate and find to get the selected zone. Each of these patterns keeps the code declarative and avoids manual loops and mutation. When you have an array of objects and need to pick a subset of keys for each, map with destructuring: items.map(({ id, name }) => ({ id, name })). When you need to add a computed property, map with spread: readings.map(r => ({ ...r, display: formatTemp(r.value), isStale: isStale(r.timestamp) })). When you filter and then need the original indices, you can map first to { item, index } then filter then map to get the items or indices: arr.map((item, i) => ({ item, i })).filter(({ item }) => test(item)).map(({ item }) => item). When you have two arrays and want to pair them by index, you can map over the indices: Array.from({ length: Math.min(a.length, b.length) }, (_, i) => [a[i], b[i]]). When the data is a mix of types (e.g. some elements are null), filter those out first: arr.filter(x => x != null) before mapping or reducing so the rest of the pipeline does not have to handle null. When you need a running total or running max, reduce can build an array of cumulative values: arr.reduce((acc, n) => [...acc, (acc[acc.length - 1] ?? 0) + n], []).

## 6) What Breaks When Array Methods Are Misused

If you mutate the array inside forEach or while iterating with for...of (push, splice, etc.), elements can be skipped or processed twice. Prefer building a new array with filter or iterating over a copy. If you use map or filter but do not assign or use the return value, the original array is unchanged and you have done work for nothing. Always use the returned array: const filtered = arr.filter(...). If you use reduce without an initial value and the array is empty, reduce throws. Pass an initial value (e.g. 0 for sum, {} for object). If you use find or findIndex and expect an element but none matches, you get undefined or -1; check before using (if (found !== undefined) ... or if (index >= 0) ...). If you use some or every on an empty array, some returns false and every returns true (vacuously). If you forget that sort mutates, the original array is reordered; use [...arr].sort() when you need to keep the original. If you pass a non-function to sort (or a function that does not return a number consistently), order can be undefined or wrong; for numbers use (a, b) => a - b. If you use map when you want side effects, you create a new array of return values (often undefined) unnecessarily; use forEach for side effects. If you use forEach when you need to break on first match, you cannot; use find or a for loop. If the callback has side effects and you use it in map or filter, those effects run for every element; that may be intended (e.g. logging) but often it is clearer to separate "compute value" (map) from "do something" (forEach). If you chain many steps and the array is empty at an early step, the rest of the chain runs on an empty array and produces an empty array or the reduce initial value—correct but worth remembering when debugging. If you treat the result of filter as the same reference as the original and mutate it, you are mutating the filtered copy; if you meant to mutate the original, that is a bug. So: do not mutate while iterating, use the return values of map/filter/reduce, provide initial value for reduce, check find/findIndex results, and copy before sort when you must not mutate. If the callback you pass to map, filter, or reduce throws, the iteration stops and the error propagates; ensure the callback does not throw for valid input, or wrap the callback body in try/catch if you want to skip or handle errors per element. If you use a method that returns a new array (map, filter, slice) and the array is very long, each step allocates memory; for one-off operations that is fine, but if you are in a hot loop or processing many chunks, a single for loop that pushes to a pre-allocated array might be more efficient. If you chain and one step returns something that is not an array (e.g. reduce returns a number), the next step in the chain must be a method that exists on that type; you cannot chain map after reduce because reduce returns a single value. So the typical chain is filter, map, maybe filter again, then reduce at the end to get one value, or filter and map and then use the array. If you need to short-circuit (e.g. "find first and then do something and stop"), do not chain; use find or a loop.

## 7) Checklist

When you work with array methods: (1) Use map to transform each element into a new value; it returns a new array. (2) Use filter to keep only elements that pass a test; it returns a new array. (3) Use reduce to get a single value (sum, max, object); always pass an initial value when the array might be empty. (4) Use forEach only for side effects; do not use its return value. (5) Use find for the first matching element, findIndex for its index; check for undefined or -1. (6) Use some for "any matches?" and every for "all match?". (7) Use flatMap when you would map and then flatten one level. (8) Copy before sort if you must not mutate: [...arr].sort(compare). (9) Do not mutate the array while iterating; prefer filter/map to build new arrays. (10) Chain filter, map, reduce when the pipeline is clear; use a loop when you need to break early or the logic is complex. Chapter 3.18 (Template Literals and Interpolation) will show how to format strings when you map or reduce arrays to display text.

## Common Pitfalls

Mutating while iterating: Changing the array (push, splice, etc.) inside forEach or for...of can skip or double-process elements. Build a new array with filter/map instead.

Ignoring map/filter return value: map and filter return new arrays; they do not change the original. Assign the result: const out = arr.map(...).

reduce without initial value: On an empty array, reduce throws if no initial value is given. Always pass an initial value when the array might be empty.

Using forEach when you need to break: forEach runs to completion. Use find or a for loop when you need to stop on first match.

sort mutates: sort() changes the array in place. Use [...arr].sort() if you need to keep the original.

sort without compare for numbers: Default sort converts to string. For numbers use (a, b) => a - b.

Using map for side effects: map builds a new array; use forEach when you only want side effects.

Assuming find always returns: find returns undefined when nothing matches. Check before using the result.

## Summary

Use map to transform each element (new array); filter to keep elements that pass a test (new array); reduce to produce a single value (sum, max, object); forEach for side effects only. Use find and findIndex for the first match; some and every for "any" or "all" checks; flat and flatMap for nested arrays; sort with a compare function for numbers or objects, and copy first if you must not mutate. Prefer methods that return new arrays over mutating while iterating; use a for loop or find when you need to break early. Chain filter, map, and reduce for clear pipelines.
